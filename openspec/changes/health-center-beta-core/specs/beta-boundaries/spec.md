# Beta boundaries

## Requirements

### Requirement: Complete beta scope is not priority-gated

Every capability approved in Wayfinder #266 and resolutions #267–#273 MUST remain in the beta scope. Implementation priority MUST NOT be interpreted as feature exclusion, delivery permission, estimate, staffing allocation, or proof of current readiness.

### Requirement: Explicit independent pending decisions

The system’s visual identity (name, logo, palette, typography) and concrete hosting/budget conditions MUST remain undecided. Specifications and later work MUST NOT invent their values, treat current Origen branding as selected, or select a cloud provider/budget by default. These pending decisions MAY block only the work that depends on them.

### Requirement: Excluded capability set

The beta MUST NOT include WhatsApp, mandatory phone verification to book, clinical records/notes/results, fines, direct rescheduling, payment receipts, partial payments, account credit/current account, refunds, automatic payment transfer, dependant booking, waiting list, advanced reports, centre-wide/comparative summaries, patient self-editing, internal change-request forms, credential verification, licence-type catalogues, per-centre branding, or performance testing.
